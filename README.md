# GitLaTeX collaboration relay

An optional, tiny server that lets a few people edit the same
[GitLaTeX](https://github.com/abdussamiakanda/gitlatex) project
in real time. It runs on Cloudflare (Workers + Durable Objects, free plan is
plenty for a handful of co-authors).

It only relays text. Every collaborator runs GitLaTeX on their own machine,
which writes the shared text to their own folder; compiling, committing and
pushing stay local.

```
 GitLaTeX (Ada) ──WebSocket──▶ Worker ─▶ Durable Object "thesis" ◀──WebSocket── GitLaTeX (Bob)
   saves, commits, compiles      (Yjs document: path → text,           saves, commits, compiles
   on Ada's machine               cursors, who is online)              on Bob's machine
```

## Deploy (in the browser)

You need a Cloudflare account (the free plan is enough) and a GitHub account.
Nothing to install, no terminal.

1. **Connect GitHub to Cloudflare first.** In the
   [Cloudflare dashboard](https://dash.cloudflare.com/?to=/:account/workers-and-pages/create),
   go to **Workers & Pages → Create application → Connect to Git**, click
   **+ Add account**, and **Install & Authorize** the *Cloudflare Workers and
   Pages* GitHub app. Once your GitHub account is listed, you can leave that
   page.
2. **Generate an admin token**: a long random string that only you know. In
   GitLaTeX, **Live collaboration → Host** (or **Settings → Collaboration**)
   has a **Generate admin token** button; a password manager works too.
3. **Click the button below**, paste the token as **ADMIN_TOKEN**, and click
   **Create and deploy**. Cloudflare copies this repository into your GitHub
   account and builds it, which takes a minute or two.

   [![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/abdussamiakanda/gitlatex-collab)

4. **Turn on the workers.dev address.** When the deploy has finished, open
   **Workers & Pages**, select the Worker (`gitlatex-collab` unless you renamed
   it), go to **Settings → Domains & Routes**, and enable **workers.dev**. The
   address it shows, e.g. `https://gitlatex-collab.<your-subdomain>.workers.dev`,
   is your relay.

Then, in GitLaTeX:

1. **You (the owner):** open the project, then **Live collaboration** in the left
   sidebar → **Host**. Enter the relay address and your admin token, click
   **Connect**, then **Create room & go live**. The room is named after the
   project, and the relay generates a token for it. Copy the **invite** from
   the panel and send it to your co-authors.
2. **Your co-authors:** open their copy of the project, then **Live
   collaboration** → **Join**, and paste the invite. Nothing to deploy.

Everyone appears under their git `user.name`. Each project gets its own room
and token, so an invite only opens the project it was made for. The panel
shows the open project's room, and **Settings → Collaboration** lists them all;
from either you can copy a room's invite again, issue a new token (everyone is
disconnected until they get the new invite) or delete a room.

To change the admin token later: the Worker's **Settings → Variables and
Secrets** in the Cloudflare dashboard. Then sign in again in GitLaTeX with the
new one.

### From a terminal instead

You need Node.js 22+.

```bash
npm install
npx wrangler login
npx wrangler secret put ADMIN_TOKEN     # choose a long random string
npx wrangler deploy
```

## Run it locally

```bash
npm install
echo "ADMIN_TOKEN=dev-admin" > .dev.vars
npx wrangler dev                         # ws://localhost:8787
```

Use `localhost:8787` as the relay address in GitLaTeX.

## API

There are two kinds of token. The **admin token** (`ADMIN_TOKEN`) belongs to
the owner: it manages rooms and can join any of them. Each **room token** is
generated by the relay when a room is created and opens only that room.
Anything else gets `401`. Room names use `a-z`, `0-9`, `.`, `_` and `-` (up
to 64 characters).

Rooms (`token` = the room's token, or the admin token):

| Request | What it does |
| --- | --- |
| `GET wss://<host>/parties/collab/<room>?token=…` | WebSocket speaking the [Yjs](https://yjs.dev) sync and awareness protocols. The document has one root map, `files`, from project-relative path to `Y.Text`. Awareness states carry `user: {name, color}` and `cursor: {path, anchor, head}` (Yjs relative positions). |
| `GET https://<host>/parties/collab/<room>?token=…` | JSON: `{ room, files: [{path, length}], peers: [name] }`, handy for checking a deployment. |

Owner (`Authorization: Bearer <ADMIN_TOKEN>`; CORS is open so GitLaTeX can
call it from the browser):

| Request | What it does |
| --- | --- |
| `GET /admin/rooms` | `{ rooms: [{room, token, createdAt}] }` |
| `POST /admin/rooms/<room>` | Creates the room with a fresh token, or returns the existing one. `{room, token, createdAt, created}` |
| `POST /admin/rooms/<room>/token` | Gives the room a new token and disconnects everyone in it. |
| `DELETE /admin/rooms/<room>` | Deletes the room, its token and its shared text, and disconnects everyone. |

GitLaTeX's invites are `gitlatex-invite:` followed by base64url JSON
`{"h": host, "r": room, "t": room token}`.

Any Yjs client can join a room, e.g. with `y-partyserver/provider`:

```ts
import * as Y from 'yjs';
import YProvider from 'y-partyserver/provider';

const doc = new Y.Doc();
const provider = new YProvider('gitlatex-collab.you.workers.dev', 'thesis', doc, {
  party: 'collab',
  params: { token: 'your-token' },
});
doc.getMap<Y.Text>('files').observeDeep(() => { /* … */ });
```

## How it behaves

- One Durable Object per room, so all edits to a room go through one place.
  Idle connections hibernate and cost nothing.
- The document is saved to the Durable Object's storage a couple of seconds
  after edits, so a room survives restarts and people can come and go.
- To start a room over, delete it and create it again.
- Rooms and their tokens are kept in a second Durable Object, the registry.
  Room tokens are stored so that you can copy an invite again later; anyone
  with access to your Cloudflare account can see them.
- A room exists only once the owner creates it; a room token never opens
  another room.
